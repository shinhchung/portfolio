MH Wilds Build Helper

Turning game reference data into a reproducible pipeline and a typed equipment-planning tool.

The problem

Equipment planning combines armor, skills, decorations, weapon slots, and monster weaknesses. A useful recommendation needs consistent data and explicit constraints.

What I built

An Expo and React Native application with TypeScript domain models, a data-refresh pipeline, and an equipment optimizer.

From sources to recommendations

  1. Ingest: download English and Traditional Chinese MHDB snapshots and retain Kiranico snapshots for cross-checking.
  2. Normalize: transform raw sources into local JSON datasets.
  3. Generate: create application-facing TypeScript data from normalized inputs.
  4. Optimize: evaluate equipment against target skills, owned decorations, weapon restrictions, and monster weaknesses.
  5. Present: show recommended equipment, skill totals, decorations, and defense information.

Design decisions

Raw snapshots, normalized data, generated application data, and recommendation logic are separate stages. This keeps the refresh workflow reproducible and makes source discrepancies easier to inspect.

Missing weapon thumbnails remain explicitly absent rather than being silently substituted. Final equipment values should be checked against the current game version.

What this demonstrates

Data ingestion and normalization, typed domain modeling, constraint-based search, and a mobile interface built on the same data model.
